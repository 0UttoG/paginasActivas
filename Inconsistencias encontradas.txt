Reporte de Pruebas Funcionales (Inconsistencias Encontradas)
Rol: Candidato

Registro - Campo Documento: El campo "DUI/Pasaporte" permite ingresar y guardar texto (letras). Sí, es un error. Debería tener validación en el frontend (type="number" o un pattern regex) y en el backend para aceptar únicamente números (y el guion del DUI).

Mi Perfil - Campo Teléfono: Permite guardar texto en lugar de números y no respeta el formato telefónico. Sí, es un error. Falta validación numérica y longitud máxima/mínima tanto en el HTML como en el controlador de Node.js.

Estadísticas del Perfil: Al guardar una vacante, esta aparece en la lista de "Vacantes guardadas", pero el contador numérico en la tarjeta de estadísticas se queda estático en "0". Sí, es un error de integración. El JS del frontend no está actualizando el DOM de ese contador tras el fetch exitoso.

Rol: Empresa
4.  Registro - Validación de Correo Existente: El sistema detecta correctamente si un correo ya está registrado y lanza alerta. Comportamiento correcto.
5.  Registro - Validación de Dominio de Correo: El sistema permitió registrar el correo holaa@gmail.co. Técnicamente no es un error de código. Los dominios .co existen (pertenecen a Colombia). No es obligatorio forzar .com a menos que sea una regla de negocio estricta del proyecto. El backend validó que tuviera formato de correo (texto@texto.dominio), lo cual es el estándar. Puedes anotarlo como "Sugerencia de mejora" en lugar de error.
6.  Registro - Campo Documento Empresa: El campo "DUI/PASAPORTE" (o NIT) permitió guardar texto. Sí, es un error, igual que en el candidato. Faltan las validaciones numéricas.
7.  Publicación de Ofertas (Empresa Pendiente): El sistema lanza una alerta de error (cuadro rojo) indicando que "la empresa debe estar aprobada para crear vacantes". Comportamiento correcto. El backend está aplicando la regla de negocio definida en el script SQL de que solo empresas verificadas pueden publicar.


La mayoría de estos detalles se arreglan rápido agregando validadores en el middleware de su backend o cambiando el tipo de input en el HTML
